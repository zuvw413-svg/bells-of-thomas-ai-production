## سير العمل المختصر

1. **البحث والتحقق:** ابدأ بالملفات الموجودة في `docs/`، ولا تعتمد على الذكاء الاصطناعي كمصدر تاريخي.
2. **الكتابة:** أنشئ/حدّث ملف الحلقة، ثم افتح مهمة GitHub للمراجعة.
3. **المرجع البصري:** ثبّت الشخصيات والمواقع في `Master_Assets/` قبل توليد اللقطات.
4. **التوليد:** احفظ المطالبات والنسخ الناتجة مع رقم إصدار وبيانات الأداة.
5. **المونتاج:** استورد اللقطات إلى DaVinci Resolve وفق `docs/04_DAVINCI_RESOLVE_WORKFLOW.md`.
6. **المراجعة:** افحص الاستمرارية والدقة والحقوق والصوت والترجمة.
7. **الإصدار:** طبّق قائمة `docs/06_RELEASE_CHECKLIST.md`.

## أدوات مقترحة

يمكن استخدام أدوات توليد الصور/الفيديو/الصوت التي يملك الفريق حقوق استخدامها. يجب تسجيل الأداة والإصدار والإعدادات في سجل الأصول. لا يحتوي المستودع على ملفات الوسائط الكبيرة؛ استخدم Git LFS أو تخزينًا خارجيًا مرخصًا، واحفظ الروابط والـ checksums فقط.

## المونتاج وDaVinci Resolve

لا ينفذ GitHub المونتاج تلقائيًا ولا يملك هذا المستودع اتصالًا مباشرًا بجهازك أو ببرنامج DaVinci Resolve. لكنه يجهز كل ما يلزم لعمل المونتير: قائمة اللقطات، أسماء موحدة، سجلات أصول، ملاحظات صوتية، وقائمة تصدير. يمكن لاحقًا إضافة ملفات `.drp` أو XML/EDL بعد إنشائها محليًا، مع عدم رفع الوسائط المحمية أو الكبيرة دون تصريح.
